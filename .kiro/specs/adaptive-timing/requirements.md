# Requirements Document

## Introduction

`adaptive-timing` adds a timing engine to the pure Dart package `packages/morse_core`. The engine turns raw switch events (press and release, each with an `int` timestamp in microseconds) into Morse Symbols, and then into letters and word spaces. Letters are looked up with the existing `CodeTable.characterFor` (`packages/morse_core/lib/src/code_table.dart`). The existing `MorseEncoder`, `MorseDecoder` and `MorseFormatException` are unchanged.

The engine is calibrated to each person. Data from the Flutter web spike showed one user whose presses lasted about 100 ms while the gaps between presses inside one letter lasted 214 to 314 ms. The textbook 1:3:7 ratio would read those inside-letter gaps as letter gaps and split every letter. The engine therefore calibrates press lengths and gap lengths separately: it measures four values from the user keying a known word (default `PARIS`) and derives every threshold from those values.

The engine offers a batch API (a full list of events in, letters and word spaces out) and an incremental API for the live UI (events fed one at a time, plus `advanceTo(now)` so a letter completes after enough silence). Unknown Symbol sequences produce an explicit unknown-letter result.

Every acceptance criterion has an ID in the style of the morse-core spec: `REQ-EVENT-n`, `REQ-DEBOUNCE-n`, `REQ-CAL-n`, `REQ-TIMING-n`, `REQ-BATCH-n`, `REQ-LIVE-n`, `REQ-ENGINE-n`, `REQ-PBT-n`. Tests and doc comments cite these IDs. None of these areas reuse a morse-core area name.

### Decisions and assumptions

These points were not fixed by the request. Each is a recorded decision, flagged for review.

- **B1. Debounce time is configuration, not a decoder constant.** The steering bans absolute time constants in the decoder. The debounce time is a field of Timing_Config, in microseconds, supplied alongside the Calibration. Its default value is 30,000 µs (30 ms), as the user asked. The default lives only in Timing_Config; classification and debounce logic read the configured value and contain no time literal. The word-gap factor (default 2.0) is a dimensionless ratio, also held in Timing_Config.
- **B2. Debounce order.** Debouncing first merges every release shorter than the debounce time, then drops every press still shorter than the debounce time. Merging first means a chattering press-down (short press, short release, long press) becomes one long press instead of losing its start. Dropping a press only lengthens the gap around it, so the result has no short gaps and no short presses, which makes debounce idempotent.
- **B3. Boundary values.** A duration exactly equal to the debounce time is kept. A press exactly equal to the press threshold is a dah. A gap exactly equal to a gap threshold falls in the longer class.
- **B4. Calibrated value statistic.** Each calibrated value is the median of the matching measured durations. For an even count, the median is the mean of the two middle values, rounded half up to a whole microsecond. The median resists one stray press or gap better than the mean.
- **B5. Calibration acceptance.** A calibration is accepted when the press count matches the word, the measured classes separate cleanly, and no calibrated value is 0 (see B14). Separating cleanly means every press expected to be a dit is shorter than every press expected to be a dah, and every gap expected inside a letter is shorter than every gap expected between letters. Expected classes come from the position in the calibration word. No minimum ratio between classes is enforced. The jitter guarantee (REQ-TIMING-7, REQ-TIMING-8) applies only to calibrations whose classes differ by a factor of at least 2.
- **B6. Word gaps are not calibrated.** The calibration word is one word, so it contains no word gap. The word-gap threshold is derived from the word-gap factor and the calibrated letter gap (see B13).
- **B7. Word spaces are emitted before the next letter.** A Word_Space is emitted when the first Symbol of the next letter is confirmed after a word-length gap. Silence at the end of input never produces a trailing Word_Space. This keeps the batch and incremental results equal and avoids a space that appears by itself on screen.
- **B8. Confirmed Symbols only.** In the incremental API, a Symbol becomes part of the Partial_Sequence only after its release is confirmed, that is, after the debounce time passes without a new press. Until then a following press could still merge with it and turn a dit into a dah.
- **B9. Two-switch mode is out of scope.** Two-switch input (one key for dit, one for dah) has no press-length classification and is left to a later spec.
- **B10. Morse-core REQ-PURE-6 is partly superseded.** morse-core REQ-PURE-6 limits the public API to `CodeTable`, `MorseEncoder`, `MorseDecoder` and `MorseFormatException`. REQ-ENGINE-4 replaces that public-API sentence only; the other clauses of REQ-PURE-6 still apply. The test that checks the exact public API must be replaced during this feature (REQ-PBT-7).
- **B11. Timestamp range.** Timestamps are limited to ±2^52 Microseconds (REQ-EVENT-1). On the web build, Dart `int` values are JavaScript doubles, so this limit keeps every timestamp and every difference between two timestamps exact. A timestamp outside the range is error kind timestamp out of range (REQ-EVENT-5).
- **B12. Calibration word length.** A Calibration_Word has at most 16 characters (REQ-CAL-3). Longer words add effort for the user without improving the medians.
- **B13. Threshold formula.** Press_Threshold and Letter_Gap_Threshold are the arithmetic midpoints of their two calibrated values, rounded up to a whole Microsecond. The Word_Gap_Threshold is Word_Gap_Factor × Letter_Gap rounded up, and at least Letter_Gap + 1 (REQ-TIMING-1). Integer comparison against a whole-Microsecond threshold is exact and scale invariant. The arithmetic midpoint also leaves more room above Symbol_Gap than a geometric midpoint, which suits the spike user whose inside-letter gaps ran long.
- **B14. Zero-duration rejection.** When the Debounce_Time is 0, a Press or Gap can last 0 Microseconds, so a median can be 0. A Calibration with a value of 0 is invalid (REQ-CAL-14), so the Calibrator returns the Rejection_Reason `zeroDuration` instead (REQ-CAL-30).
- **B15. Enums are public types.** Public enums, such as error kinds and Rejection_Reasons, count as public types. Each goes in its own file, one public type per file (REQ-ENGINE-3). B15 amends morse-core REQ-PURE-4 so that its one-public-class-per-file rule covers public enums as well as classes.
- **B16. Doc comment IDs.** For Timing_Engine files, REQ-ENGINE-6 replaces the morse-core REQ-PURE-7 rule that cited IDs must come from the morse-core document. Timing_Engine doc comments may cite IDs from either document.
- **B17. Value caps.** A Word_Gap_Factor greater than 1,000 is invalid (REQ-DEBOUNCE-3), and a Dit_Length, Dah_Length, Symbol_Gap or Letter_Gap greater than 2^40 (1,099,511,627,776) Microseconds is invalid (REQ-CAL-14). Together the caps keep the Word_Gap_Threshold at or below 1,000 × 2^40, which is less than 2^53, so the threshold stays exact on the web build and within the Dart VM `int` range.

## Glossary

- **Morse_Core**: The pure Dart package `packages/morse_core`.
- **Code_Table**: The existing `CodeTable` class in `packages/morse_core/lib/src/code_table.dart`, with 43 ITU-R M.1677-1 entries and the reverse lookup `characterFor`.
- **Timing_Engine**: The set of new Morse_Core components defined in this document: Debouncer, Calibrator, Classifier, Batch_Decoder and Live_Decoder.
- **Microsecond**: The time unit of every timestamp and duration, held as a Dart `int`.
- **Switch_Event**: A press (switch closed) or a release (switch opened), with a timestamp in Microseconds.
- **Event_Sequence**: An ordered list of Switch_Events.
- **Valid_Event_Sequence**: An Event_Sequence that is empty, or that starts with a press, alternates press and release, ends with a release, has timestamps that never decrease, and has every timestamp within the range in REQ-EVENT-1.
- **Press**: One press Switch_Event and the release that follows it. Its duration is the release timestamp minus the press timestamp.
- **Gap**: The interval between the release of one Press and the press of the next Press. Its duration is the later timestamp minus the earlier.
- **Debounce_Time**: The configured duration, in Microseconds, below which a Press or a Gap counts as switch bounce.
- **Word_Gap_Factor**: The configured dimensionless number used with the calibrated Letter_Gap to derive the Word_Gap_Threshold.
- **Timing_Config**: The value holding Debounce_Time (default 30,000) and Word_Gap_Factor (default 2.0).
- **Debouncer**: The Timing_Engine component that removes switch bounce from a list of Presses.
- **Symbol**: A dit `.` or a dah `-`, as in the morse-core spec.
- **Calibration_Word**: The word the user keys to calibrate. Default `PARIS`.
- **Calibrator**: The Timing_Engine component that measures a Calibration from an Event_Sequence keyed for a Calibration_Word.
- **Calibration**: The value holding four positive durations in Microseconds, each at most 2^40 (REQ-CAL-14): Dit_Length, Dah_Length, Symbol_Gap and Letter_Gap.
- **Dit_Length**: The calibrated duration of a Press meant as a dit.
- **Dah_Length**: The calibrated duration of a Press meant as a dah.
- **Symbol_Gap**: The calibrated duration of a Gap between two Presses inside one letter.
- **Letter_Gap**: The calibrated duration of a Gap between two letters inside one word.
- **Calibration_Rejection**: The result the Calibrator returns instead of a Calibration. It carries one Rejection_Reason and an English message.
- **Rejection_Reason**: One of `unsuitableWord`, `invalidEvents`, `wrongPressCount`, `pressesOverlap`, `gapsOverlap`, `zeroDuration`, `durationTooLong`.
- **Classifier**: The Timing_Engine component that turns Press and Gap durations into classes using thresholds derived from a Calibration and a Timing_Config.
- **Press_Threshold**: The duration, derived from Dit_Length and Dah_Length as in REQ-TIMING-1, at or above which a Press is a dah.
- **Letter_Gap_Threshold**: The duration, derived from Symbol_Gap and Letter_Gap as in REQ-TIMING-1, at or above which a Gap ends a letter.
- **Word_Gap_Threshold**: The smallest whole number of Microseconds that is greater than Letter_Gap and not less than Word_Gap_Factor × Letter_Gap (REQ-TIMING-1). A Gap at or above this duration ends a word.
- **Decoded_Item**: One output element: a Letter_Item, an Unknown_Letter_Item or a Word_Space.
- **Letter_Item**: A Decoded_Item carrying the uppercase character that Code_Table maps the letter's Symbol sequence to.
- **Unknown_Letter_Item**: A Decoded_Item carrying a non-empty Symbol sequence that is not a Morse_Code in the Code_Table.
- **Word_Space**: A Decoded_Item that separates two words.
- **Batch_Decoder**: The Timing_Engine component that turns a whole Event_Sequence into a list of Decoded_Items.
- **Live_Decoder**: The Timing_Engine component that accepts Switch_Events one at a time and `advanceTo(now)` calls, and exposes the Decoded_Items so far and the Partial_Sequence.
- **Partial_Sequence**: The confirmed Symbols of the letter the Live_Decoder is currently building.
- **Pending_Press**: In the Live_Decoder, a Press whose press Switch_Event has been received and whose Symbol has not yet been appended to the Partial_Sequence or discarded: the switch is still pressed, or the Press was released less than the Debounce_Time before the latest received timestamp.
- **Timing_Input_Error**: The error the Timing_Engine raises for an invalid Event_Sequence, a timestamp out of range (REQ-EVENT-5), an invalid live call, an invalid Press list given to the Debouncer (REQ-DEBOUNCE-20), a negative duration given to the Classifier (REQ-TIMING-11), or an invalid Timing_Config or Calibration. It carries a zero-based event or Press index (where one is involved) and an error kind.
- **Ideal_Timing**: An Event_Sequence generated for a text from a Calibration: every dit Press lasts Dit_Length, every dah Press lasts Dah_Length, every Gap inside a letter lasts Symbol_Gap, every Gap between letters lasts Letter_Gap, and every Gap between words lasts 1.5 times the Word_Gap_Threshold, rounded to the nearest Microsecond.
- **Well_Separated_Calibration**: A Calibration and Timing_Config where Dah_Length ≥ 2 × Dit_Length, Letter_Gap ≥ 2 × Symbol_Gap, Word_Gap_Factor ≥ 1.5, and Debounce_Time ≤ 0.5 × the smaller of Dit_Length and Symbol_Gap.

## Requirements

### Requirement 1: Switch events

**User Story:** As a Sounder developer, I want one exact definition of valid switch input, so that the input adapters and the timing engine agree on what they exchange.

#### Acceptance Criteria

1. REQ-EVENT-1: THE Timing_Engine SHALL represent each Switch_Event as a kind (press or release) and a timestamp in Microseconds held as a Dart `int`, and SHALL accept any timestamp from −4,503,599,627,370,496 to 4,503,599,627,370,496 inclusive (±2^52), including zero and negative values, because only differences between timestamps are used and every such difference stays exact on the web build.
2. REQ-EVENT-2: WHEN the Batch_Decoder, created with a Calibration and Timing_Config that pass REQ-CAL-14, REQ-DEBOUNCE-3 and REQ-TIMING-9, or the Calibrator receives a Valid_Event_Sequence, THE Timing_Engine SHALL process the Event_Sequence without raising a Timing_Input_Error. This includes the empty Event_Sequence and sequences that contain Presses or Gaps of zero duration. The Batch_Decoder SHALL return a list of Decoded_Items. The Calibrator SHALL return either a Calibration or a Calibration_Rejection.
3. REQ-EVENT-3: IF the Batch_Decoder receives an Event_Sequence that is not a Valid_Event_Sequence, THEN THE Batch_Decoder SHALL check the raw events before any debounce and raise one Timing_Input_Error, return no partial result, and expose the error kind as a value that tests can compare. The Batch_Decoder SHALL scan the events in index order and report the lowest index at which a rule breaks. At that index, the kinds take precedence in this order: timestamp out of range (REQ-EVENT-5), starts with release (index 0), two presses in a row, two releases in a row, decreasing timestamp (the index of the event whose timestamp is lower than the one before it). The kind ends with press SHALL be reported only when no earlier rule breaks, and it carries the index of the last event.
4. REQ-EVENT-4: WHEN the Timing_Engine raises a Timing_Input_Error, THE Timing_Input_Error SHALL include an English message that contains one fixed phrase per error kind, with each kind's phrase different from every other kind's. Where an event is involved, the message SHALL also contain the zero-based event index as a decimal integer. The message SHALL contain no Symbol, no decoded character and no timestamp value.
5. REQ-EVENT-5: IF the Batch_Decoder, the Calibrator or the Live_Decoder receives a timestamp outside the range in REQ-EVENT-1, THEN THE Timing_Engine SHALL treat it as error kind timestamp out of range. The Batch_Decoder SHALL raise it as in REQ-EVENT-3. The Calibrator SHALL return it as `invalidEvents` as in REQ-CAL-11. The Live_Decoder SHALL raise it and leave its state unchanged as in REQ-LIVE-9.
6. REQ-EVENT-6: WHEN the Batch_Decoder or the Calibrator processes an Event_Sequence, THE Timing_Engine SHALL leave the caller's Event_Sequence unchanged: the same length, order, kinds and timestamps. This holds whether processing succeeds, raises a Timing_Input_Error or returns a Calibration_Rejection.

### Requirement 2: Timing configuration

**User Story:** As a speech-language therapist, I want to adjust the debounce time and the word gap for a person, so that the engine fits their switch and their rhythm.

#### Acceptance Criteria

1. REQ-DEBOUNCE-1: THE Timing_Config SHALL hold a Debounce_Time in Microseconds as a Dart `int` with a default value of 30,000 and a Word_Gap_Factor as a Dart `double` with a default value of 2.0. Each field the caller leaves out SHALL take its default value, and each field the caller supplies SHALL read back exactly as supplied.
2. REQ-DEBOUNCE-2: THE Debouncer, Calibrator, Classifier, Batch_Decoder and Live_Decoder SHALL read the Debounce_Time and the Word_Gap_Factor only from the Timing_Config they are given. Their source code SHALL contain no numeric literal standing for a duration or for the word-gap ratio, and the only place the defaults of 30,000 and 2.0 appear SHALL be the Timing_Config.
3. REQ-DEBOUNCE-3: IF a Timing_Config is created with a negative Debounce_Time, or with a Word_Gap_Factor that is NaN, infinite, less than or equal to 1.0, or greater than 1,000 (the valid range is finite, greater than 1.0 and at most 1,000), THEN THE Timing_Config SHALL raise a Timing_Input_Error whose error kind names the invalid field and SHALL create no Timing_Config. IF both fields are invalid, THEN THE Timing_Input_Error SHALL name the Debounce_Time.
4. REQ-DEBOUNCE-13: WHEN the Batch_Decoder receives a single Press lasting 20,000 Microseconds with a Calibration of Dit_Length 100,000, Dah_Length 300,000, Symbol_Gap 250,000 and Letter_Gap 700,000, THE Batch_Decoder SHALL return an empty list under a Timing_Config with Debounce_Time 30,000, and one Letter_Item `E` under a Timing_Config with Debounce_Time 10,000.
5. REQ-DEBOUNCE-14: WHEN a Timing_Config is created with a Debounce_Time of 0, or with a Word_Gap_Factor of 1.5, THE Timing_Config SHALL be created without error. IF a Timing_Config is created with a Debounce_Time of -1, or with a Word_Gap_Factor of exactly 1.0, THEN THE Timing_Config SHALL raise the Timing_Input_Error defined in REQ-DEBOUNCE-3.

### Requirement 3: Debounce

**User Story:** As a person using one switch, I want switch bounce ignored, so that one physical press counts as exactly one press.

#### Acceptance Criteria

In this section, a Press written as (a, b) has press timestamp a and release timestamp b, both in Microseconds. "Shorter than" means strictly less than, as in Decision B3.

1. REQ-DEBOUNCE-4: WHEN the Debouncer receives a list of Presses in time order and a Debounce_Time, THE Debouncer SHALL first merge every run of consecutive Presses whose Gaps are all shorter than the Debounce_Time into one Press. The merged Press SHALL start at the press timestamp of the first Press in the run and end at the release timestamp of the last Press in the run. A Gap equal to the Debounce_Time SHALL NOT cause a merge.
2. REQ-DEBOUNCE-5: WHEN the Debouncer has completed the merges of REQ-DEBOUNCE-4, THE Debouncer SHALL remove every Press whose duration is shorter than the Debounce_Time, and SHALL NOT perform any further merge after a removal.
3. REQ-DEBOUNCE-6: THE Debouncer SHALL return its Presses in time order. Every press and release timestamp in the result SHALL be a timestamp from the input. Every input Press that lasts at least the Debounce_Time and is not merged under REQ-DEBOUNCE-4 SHALL appear in the result with unchanged timestamps. The list the caller passed in SHALL remain unchanged.
4. REQ-DEBOUNCE-7: FOR ALL time-ordered lists of 0 to 50 Presses with Press and Gap durations from 0 to 2,000,000 Microseconds, and all Debounce_Times from 0 to 100,000 Microseconds, THE Debouncer SHALL return a list with no more Presses than the input, in which every Press and every Gap lasts at least the Debounce_Time (debounced output property).
5. REQ-DEBOUNCE-8: FOR ALL inputs in the ranges of REQ-DEBOUNCE-7, debouncing the Debouncer output again with the same Debounce_Time SHALL return a list equal to that output (idempotence property).
6. REQ-DEBOUNCE-9: FOR ALL Valid_Event_Sequences and Timing_Configs, THE Batch_Decoder SHALL produce no Symbol from a Press whose duration after the merges of REQ-DEBOUNCE-4 is shorter than the Debounce_Time, and SHALL produce exactly one Symbol per Press in the Debouncer output (no-bounce-symbol property).
7. REQ-DEBOUNCE-10: WHEN the Debouncer receives a time-ordered list of Presses with a Debounce_Time of 0, THE Debouncer SHALL return a list equal to the input, including Presses and Gaps of duration 0.
8. REQ-DEBOUNCE-11: WHEN the Debouncer receives Presses (0, 2,000), (4,000, 100,000) with a Debounce_Time of 30,000, THE Debouncer SHALL return the single Press (0, 100,000).
9. REQ-DEBOUNCE-12: WHEN the Debouncer receives Presses (0, 100,000), (400,000, 410,000), (700,000, 800,000) with a Debounce_Time of 30,000, THE Debouncer SHALL return the Presses (0, 100,000) and (700,000, 800,000).
10. REQ-DEBOUNCE-20: IF the Debouncer receives a list that contains a Press whose release timestamp is earlier than its press timestamp, or a Press whose press timestamp is earlier than the previous Press's release timestamp, THEN THE Debouncer SHALL raise a Timing_Input_Error. The error SHALL carry the zero-based index of the first such Press and an error kind naming the broken rule, and the Debouncer SHALL return no partial result.
11. REQ-DEBOUNCE-21: WHEN the Debouncer receives Presses (0, 30,000), (60,000, 160,000), (189,999, 290,000) with a Debounce_Time of 30,000, THE Debouncer SHALL return the Presses (0, 30,000) and (60,000, 290,000).
12. REQ-DEBOUNCE-22: WHEN the Debouncer receives Presses (0, 5,000), (10,000, 15,000), (20,000, 120,000), (500,000, 502,000), (510,000, 512,000) with a Debounce_Time of 30,000, THE Debouncer SHALL return the single Press (0, 120,000).

### Requirement 4: Calibration word

**User Story:** As a person setting up Sounder, I want to calibrate with a known word, so that the engine learns my own rhythm.

#### Acceptance Criteria

1. REQ-CAL-1: WHEN the caller supplies no Calibration_Word, THE Calibrator SHALL use `PARIS` as the Calibration_Word.
2. REQ-CAL-2: WHEN the Calibrator has a suitable Calibration_Word, THE Calibrator SHALL derive the expected Symbol of every Press, in order, by concatenating the Code_Table Morse_Codes of the Calibration_Word's characters from first to last. It SHALL classify every Gap between two Symbols of the same character as inside a letter, and every Gap between the last Symbol of one character and the first Symbol of the next as between letters. It SHALL therefore expect a Press count equal to the total Symbol count, an inside-letter Gap count equal to the sum over all characters of (Symbol count − 1), and a between-letters Gap count equal to the character count − 1.
3. REQ-CAL-3: IF the Calibration_Word is empty, has more than 16 characters, contains a space or any character for which `CodeTable.codeFor` returns null, has fewer than two characters, contains no dit, contains no dah, or has no character whose Morse_Code has two or more Symbols, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `unsuitableWord` whose message names the first failed rule in the order listed here. THE Calibrator SHALL return this rejection whatever Event_Sequence it receives, including an empty or invalid one.
4. REQ-CAL-4: WHEN the Calibrator receives the default Calibration_Word, THE Calibrator SHALL expect exactly 14 Presses with the Symbols `.--.` `.-` `.-.` `..` `...` in that order (10 dits and 4 dahs), 13 Gaps of which the zero-based Gaps 3, 5, 8 and 10 are between letters (4 Gaps) and the other 9 are inside letters.
5. REQ-CAL-20: WHEN the caller supplies a Calibration_Word, THE Calibrator SHALL use that word, matching characters through `CodeTable.codeFor`, so that a word differing only in ASCII letter case (for example `paris` and `PARIS`) gives the same expected Symbols, Gap classes and Calibration result.
6. REQ-CAL-21: WHEN the Calibrator receives any of the Calibration_Words `E` (fewer than two characters), `EEE` (no dah), `TM` (no dit), `ET` (no character with two or more Symbols), `SO S` (contains a space) or `S#S` (character not in the Code_Table), THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `unsuitableWord`.

### Requirement 5: Calibration measurement

**User Story:** As a person with my own pace, I want my press lengths and my gap lengths measured separately, so that slow gaps inside a letter do not split my letters.

#### Acceptance Criteria

1. REQ-CAL-5: WHEN the Calibrator receives a Valid_Event_Sequence and a Calibration_Word that passes REQ-CAL-3, THE Calibrator SHALL debounce the Presses with the Debounce_Time of the Timing_Config it is given before it counts or measures anything. If the caller gives no Timing_Config, the Calibrator SHALL use the default Timing_Config (Debounce_Time 30,000, Word_Gap_Factor 2.0).
2. REQ-CAL-6: IF none of the rejection conditions in REQ-CAL-3, REQ-CAL-8, REQ-CAL-9, REQ-CAL-10, REQ-CAL-11 and REQ-CAL-30 applies, THEN THE Calibrator SHALL return a Calibration with these values. Dit_Length is the median duration of the debounced Presses expected to be dits. Dah_Length is the median duration of the debounced Presses expected to be dahs. Symbol_Gap is the median duration of the Gaps between debounced Presses expected inside letters. Letter_Gap is the median duration of the Gaps between debounced Presses expected between letters. The expected class of the n-th debounced Press and the n-th Gap is the class REQ-CAL-2 assigns to the same position.
3. REQ-CAL-7: THE Calibrator SHALL compute the median of an odd count of durations as the middle duration after sorting. For an even count, the median SHALL be the mean of the two middle durations, rounded half up to a whole Microsecond. For example, the median of 100,000 and 100,001 is 100,001, and the median of 100,000 and 100,002 is 100,001.
4. REQ-CAL-8: IF the number of debounced Presses differs from the number of Symbols in the Calibration_Word, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `wrongPressCount`. Its message SHALL state the expected number of Presses and the number received after debounce, each as a decimal integer. This includes the case where debounce leaves zero Presses.
5. REQ-CAL-9: IF the longest debounced Press expected to be a dit lasts as long as or longer than the shortest debounced Press expected to be a dah, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `pressesOverlap` and a message stating that short and long presses could not be told apart.
6. REQ-CAL-10: IF the longest Gap expected inside a letter lasts as long as or longer than the shortest Gap expected between letters, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `gapsOverlap` and a message stating that pauses inside letters and pauses between letters could not be told apart.
7. REQ-CAL-11: IF the Calibrator receives an Event_Sequence that is not a Valid_Event_Sequence, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `invalidEvents` instead of raising a Timing_Input_Error. The message SHALL contain the zero-based index of the first event that breaks the definition, as a decimal integer, and the broken rule, using the same index and rule REQ-EVENT-3 defines.
8. REQ-CAL-12: IF more than one rejection condition applies, THEN THE Calibrator SHALL return only the reason that comes first in the order `unsuitableWord`, `invalidEvents`, `wrongPressCount`, `pressesOverlap`, `gapsOverlap`, `zeroDuration`, `durationTooLong`. For example, an invalid Event_Sequence keyed for an empty Calibration_Word returns `unsuitableWord`.
9. REQ-CAL-13: THE Calibration_Rejection message SHALL be non-empty English text. It SHALL contain no timestamp, no measured duration and no Symbol. It SHALL contain the expected and received Press counts only for `wrongPressCount`, and an event index only for `invalidEvents`.
10. REQ-CAL-14: IF a Calibration is created directly with any of these values, THEN THE Calibration SHALL raise a Timing_Input_Error that names the first invalid field in the order Dit_Length, Dah_Length, Symbol_Gap, Letter_Gap: a Dit_Length, Dah_Length, Symbol_Gap or Letter_Gap of 0 or less; a Dit_Length, Dah_Length, Symbol_Gap or Letter_Gap greater than 2^40 (1,099,511,627,776) Microseconds; a Dah_Length less than or equal to the Dit_Length; or a Letter_Gap less than or equal to the Symbol_Gap.
11. REQ-CAL-15: FOR ALL Calibrations that pass REQ-CAL-14, all Calibration_Words that pass REQ-CAL-3, and all Timing_Configs whose Debounce_Time is not greater than the smaller of Dit_Length and Symbol_Gap, calibrating from the Ideal_Timing of that Calibration_Word, starting at any timestamp, SHALL return a Calibration with exactly the same Dit_Length, Dah_Length, Symbol_Gap and Letter_Gap (calibration round-trip property).
12. REQ-CAL-16: WHEN the Calibrator receives `PARIS` with the default Timing_Config, keyed from a first press at timestamp 0 with every dit Press lasting 100,000, every dah Press lasting 300,000, every Gap inside a letter lasting 250,000 and every Gap between letters lasting 700,000, THE Calibrator SHALL return a Calibration of Dit_Length 100,000, Dah_Length 300,000, Symbol_Gap 250,000 and Letter_Gap 700,000.
13. REQ-CAL-30: IF none of the conditions in REQ-CAL-3 and REQ-CAL-8 to REQ-CAL-11 applies, and any of the four computed medians is 0, THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `zeroDuration` and a message stating that a press or pause was too short to measure. A median of 0 can only occur when the Debounce_Time is 0.
14. REQ-CAL-31: WHEN the Calibrator is called, THE Calibrator SHALL return exactly one result and SHALL raise no error. That result is either a Calibration that passes REQ-CAL-14 or a Calibration_Rejection, and the Calibrator SHALL return no partial Calibration alongside a Calibration_Rejection. IF no earlier rejection condition applies and any of the four computed medians is greater than 2^40 Microseconds (the REQ-CAL-14 cap, reachable because timestamps span ±2^52), THEN THE Calibrator SHALL return a Calibration_Rejection with Rejection_Reason `durationTooLong` and a message stating that a press or pause was too long to measure.

### Requirement 6: Classification

**User Story:** As a person using Sounder, I want each press and pause judged against my own calibrated rhythm, so that my letters come out as I meant them.

#### Acceptance Criteria

1. REQ-TIMING-1: THE Classifier SHALL expose three thresholds as whole Microseconds, each computed only from the listed values with no other duration involved: Press_Threshold as the arithmetic midpoint of Dit_Length and Dah_Length rounded up, that is ⌈(Dit_Length + Dah_Length) / 2⌉; Letter_Gap_Threshold as ⌈(Symbol_Gap + Letter_Gap) / 2⌉; and Word_Gap_Threshold as the smallest whole number of Microseconds that is greater than Letter_Gap and not less than Word_Gap_Factor × Letter_Gap.
2. REQ-TIMING-2: FOR ALL Calibrations and Timing_Configs, THE Classifier SHALL produce a Press_Threshold greater than Dit_Length and less than or equal to Dah_Length, a Letter_Gap_Threshold greater than Symbol_Gap and less than or equal to Letter_Gap, and a Word_Gap_Threshold greater than Letter_Gap (threshold ordering property).
3. REQ-TIMING-3: WHEN the Classifier classifies a Press duration of zero or more Microseconds, THE Classifier SHALL return a dit if the duration is shorter than the Press_Threshold, and a dah if the duration is equal to or longer than the Press_Threshold.
4. REQ-TIMING-4: WHEN the Classifier classifies a Gap duration of zero or more Microseconds, THE Classifier SHALL return inside-letter if the duration is shorter than the Letter_Gap_Threshold, between-letters if the duration is at least the Letter_Gap_Threshold and shorter than the Word_Gap_Threshold, and between-words if the duration is at least the Word_Gap_Threshold.
5. REQ-TIMING-5: WHEN the Classifier classifies Press durations with a Calibration of Dit_Length 100,000 and Dah_Length 300,000, THE Classifier SHALL report a Press_Threshold of 200,000, SHALL return a dit for 100,000, 120,000 and 199,999, and SHALL return a dah for 200,000, 240,000 and 300,000. WHEN the Dah_Length is 300,001 instead, THE Classifier SHALL report a Press_Threshold of 200,001 and SHALL return a dit for 200,000 and a dah for 200,001.
6. REQ-TIMING-6: WHEN the Classifier classifies Gap durations with a Calibration of Symbol_Gap 250,000 and Letter_Gap 700,000 and the default Word_Gap_Factor, THE Classifier SHALL report a Letter_Gap_Threshold of 475,000 and a Word_Gap_Threshold of 1,400,000, SHALL return inside-letter for 214,000, 314,000 and 474,999, between-letters for 475,000, 700,000 and 1,399,999, and between-words for 1,400,000. WHEN the Word_Gap_Factor is 2.5 and the Letter_Gap is 700,001, THE Classifier SHALL report a Word_Gap_Threshold of 1,750,003.
7. REQ-TIMING-7: WHILE the Calibration and Timing_Config form a Well_Separated_Calibration, THE Classifier SHALL classify every Press lasting at most 1.2 × Dit_Length as a dit and every Press lasting at least 0.8 × Dah_Length as a dah, with each bound compared as an exact real number against the whole-Microsecond duration (press jitter property).
8. REQ-TIMING-8: WHILE the Calibration and Timing_Config form a Well_Separated_Calibration, THE Classifier SHALL classify every Gap lasting at most 1.2 × Symbol_Gap as inside-letter, every Gap lasting from 0.8 × Letter_Gap to 1.2 × Letter_Gap inclusive as between-letters, and every Gap lasting at least 1.2 × the Word_Gap_Threshold as between-words, with each bound compared as an exact real number against the whole-Microsecond duration (gap jitter property).
9. REQ-TIMING-9: IF the Batch_Decoder or the Live_Decoder is created with a Timing_Config whose Debounce_Time is greater than the Calibration's Dit_Length or greater than its Symbol_Gap, THEN THE Timing_Engine SHALL raise a Timing_Input_Error that names the Debounce_Time and SHALL create no decoder. A Debounce_Time equal to Dit_Length or Symbol_Gap SHALL be accepted.
10. REQ-TIMING-10: FOR ALL Calibrations, Word_Gap_Factors that are multiples of 0.25 from 1.25 to 8.0, durations from 0 to 10 × the Word_Gap_Threshold, and whole-number factors k from 1 to 1,000, THE Classifier SHALL return the same class for k × the duration under the Calibration with every value multiplied by k as it returns for the original duration under the original Calibration (classification scale invariance property).
11. REQ-TIMING-11: IF the Classifier is asked to classify a Press or Gap duration that is negative, THEN THE Classifier SHALL raise a Timing_Input_Error that names the negative duration as the broken rule, and SHALL return no class.

### Requirement 7: Batch decoding

**User Story:** As a Sounder developer, I want to decode a whole recorded sequence at once, so that tests, the evaluation runner and replays get letters and spaces from one call.

#### Acceptance Criteria

1. REQ-BATCH-1: WHEN the Batch_Decoder receives a Valid_Event_Sequence, a Calibration and a Timing_Config, THE Batch_Decoder SHALL debounce the Presses as in REQ-DEBOUNCE-4 and REQ-DEBOUNCE-5, measure each Gap between consecutive debounced Presses, classify each debounced Press and Gap as in REQ-TIMING-3 and REQ-TIMING-4, group consecutive Symbols separated by inside-letter Gaps into one letter, and return one Decoded_Item per letter in time order. It SHALL put exactly one Word_Space between two letters separated by a between-words Gap and no Word_Space between two letters separated by a between-letters Gap.
2. REQ-BATCH-2: WHEN a letter's Symbol sequence is a Morse_Code in the Code_Table, THE Batch_Decoder SHALL return a Letter_Item carrying the character that `CodeTable.characterFor` returns for that sequence.
3. REQ-BATCH-3: IF a letter's Symbol sequence is not a Morse_Code in the Code_Table, THEN THE Batch_Decoder SHALL return an Unknown_Letter_Item carrying that Symbol sequence in its original order, raise no error, and decode the rest of the Event_Sequence under the same rules as if the letter had been known.
4. REQ-BATCH-4: THE Batch_Decoder SHALL return a list that starts and ends with a Letter_Item or Unknown_Letter_Item and contains no two consecutive Word_Spaces. The list SHALL be empty when the Event_Sequence is empty or when debounce removes every Press.
5. REQ-BATCH-5: WHEN the Batch_Decoder receives the Ideal_Timing of `SOS`, starting at timestamp 0, for a Calibration of Dit_Length 100,000, Dah_Length 300,000, Symbol_Gap 250,000 and Letter_Gap 700,000 with the default Timing_Config, THE Batch_Decoder SHALL return exactly three Letter_Items `S`, `O`, `S` and no other Decoded_Item.
6. REQ-BATCH-6: WHEN the Batch_Decoder receives the Ideal_Timing of `HI THERE`, starting at timestamp 0, for the Calibration in REQ-BATCH-5 with the default Timing_Config, THE Batch_Decoder SHALL return exactly Letter_Items `H`, `I`, one Word_Space, then Letter_Items `T`, `H`, `E`, `R`, `E`.
7. REQ-BATCH-7: WHEN the Batch_Decoder receives seven Presses of 100,000 each, separated by Gaps of 250,000, for the Calibration in REQ-BATCH-5 with the default Timing_Config, THE Batch_Decoder SHALL return exactly one Unknown_Letter_Item carrying `.......`.
8. REQ-BATCH-8: FOR ALL texts of 1 to 20 characters made of Code_Table characters and single spaces, with no leading or trailing space, all Well_Separated_Calibrations whose Dit_Length, Dah_Length, Symbol_Gap and Letter_Gap are each at least 1,000 Microseconds, and every Event_Sequence made from the Ideal_Timing of that text by multiplying each Press and Gap duration independently by a factor from 0.8 to 1.2 inclusive, rounding each to the nearest Microsecond, and rebuilding the timestamps from 0 by adding the durations in order, THE Batch_Decoder SHALL return exactly one Letter_Item per non-space character of the text carrying that character, in order, and exactly one Word_Space per space, with no Unknown_Letter_Item (jitter tolerance property).
9. REQ-BATCH-9: FOR ALL Valid_Event_Sequences, Calibrations, Timing_Configs and factors k from 0.25 to 4 inclusive, scaling the input SHALL leave the Batch_Decoder output unchanged (scale invariance property). Scaling means: keep the first timestamp, multiply every Press and Gap duration by k and round each to the nearest Microsecond, rebuild the later timestamps by adding the scaled durations in order, and multiply Dit_Length, Dah_Length, Symbol_Gap, Letter_Gap and Debounce_Time by k, rounding each to the nearest Microsecond. Word_Gap_Factor stays unchanged. The property applies to generated inputs in which, before scaling, every Press, Gap and Calibration duration is at least 1,000 Microseconds and no Press or Gap duration lies within 1 percent of the Debounce_Time, the Press_Threshold, the Letter_Gap_Threshold or the Word_Gap_Threshold. The 1 percent margin applies both to the raw Press and Gap durations and to the post-debounce durations: every merged Press, and every Gap between consecutive debounced Presses, including a Gap that contains a dropped Press.
10. REQ-BATCH-10: WHEN the Batch_Decoder receives Presses (0, 150,000) and (160,000, 300,000) for the Calibration in REQ-BATCH-5 with the default Timing_Config, THE Batch_Decoder SHALL merge them into one Press of 300,000 and return exactly one Letter_Item `T`.
11. REQ-BATCH-11: WHEN the Batch_Decoder receives Presses (0, 100,000), (350,000, 360,000) and (1,000,000, 1,100,000) for the Calibration in REQ-BATCH-5 with the default Timing_Config, THE Batch_Decoder SHALL drop the 10,000 Press, measure the remaining Gap as 900,000, and return exactly two Letter_Items `E`, `E` with no Word_Space.
12. REQ-BATCH-12: WHEN the Batch_Decoder receives the seven Presses of REQ-BATCH-7, then a Gap of 700,000, then one Press of 100,000, for the Calibration in REQ-BATCH-5 with the default Timing_Config, THE Batch_Decoder SHALL return exactly one Unknown_Letter_Item carrying `.......` followed by one Letter_Item `E`.

### Requirement 8: Incremental decoding

**User Story:** As a person using the Key screen, I want each letter to appear as soon as I pause, and to see the dits and dahs of the letter I am keying, so that I can follow my input while I type.

#### Acceptance Criteria

1. REQ-LIVE-1: THE Live_Decoder SHALL be created with one Calibration and one Timing_Config, and SHALL accept a press call, a release call and an `advanceTo(now)` call, each with a timestamp in Microseconds held as a Dart `int`.
2. REQ-LIVE-2: THE Live_Decoder SHALL expose the list of completed Decoded_Items, the Partial_Sequence, and whether the switch is currently pressed. A newly created Live_Decoder SHALL hold an empty list of completed Decoded_Items, an empty Partial_Sequence and a not-pressed state, and reading these values SHALL not change them.
3. REQ-LIVE-3: WHEN the Live_Decoder receives a valid press call, THE Live_Decoder SHALL report the switch as pressed before the call returns. WHEN it receives a valid release call, it SHALL report the switch as not pressed before the call returns.
4. REQ-LIVE-4: WHEN an `advanceTo(now)` call or a press call at time now arrives with now minus the latest release timestamp at least the Debounce_Time, and the released Press lasts at least the Debounce_Time, THE Live_Decoder SHALL classify that Press as in REQ-TIMING-3 and append its Symbol to the Partial_Sequence before the call returns. Until that happens, the Partial_Sequence SHALL not include the Symbol of that Press.
5. REQ-LIVE-5: WHEN a press call arrives with its timestamp minus the previous release timestamp shorter than the Debounce_Time, THE Live_Decoder SHALL merge the new Press with the previous Press as in REQ-DEBOUNCE-4, so that the merged Press starts at the earlier press timestamp, and SHALL append no Symbol for the previous Press.
6. REQ-LIVE-6: WHEN an `advanceTo(now)` call or a press call at time now arrives while the Partial_Sequence is not empty, and either no Pending_Press exists and now minus the release timestamp of the last Press appended to the Partial_Sequence is at least the Letter_Gap_Threshold, or the Pending_Press's press timestamp minus the release timestamp of the last Press appended to the Partial_Sequence is at least the Letter_Gap_Threshold, THE Live_Decoder SHALL apply REQ-LIVE-4 first, then append one Letter_Item or Unknown_Letter_Item for the Partial_Sequence as in REQ-BATCH-2 and REQ-BATCH-3, and empty the Partial_Sequence, all before the call returns.
7. REQ-LIVE-7: WHEN the Symbol of the first Press of a letter is appended to the Partial_Sequence, the list of completed Decoded_Items is not empty, and the Gap from the release of the last Press of the previous letter to the press of this Press is at least the Word_Gap_Threshold, THE Live_Decoder SHALL append exactly one Word_Space to the completed Decoded_Items. The Word_Space then comes before the Decoded_Item of the new letter. Silence alone SHALL never append a Word_Space.
8. REQ-LIVE-8: THE Live_Decoder SHALL only append to its list of completed Decoded_Items, and SHALL leave every Decoded_Item unchanged once appended.
9. REQ-LIVE-9: IF the Live_Decoder receives a press call while pressed, a release call while not pressed, any call whose timestamp is earlier than the latest timestamp it has received, or any call whose timestamp is outside the range in REQ-EVENT-1 (timestamp out of range, REQ-EVENT-5), THEN THE Live_Decoder SHALL raise a Timing_Input_Error whose error kind names the broken rule and whose message follows REQ-EVENT-4. It SHALL also keep its completed Decoded_Items, Partial_Sequence, pressed state and latest received timestamp unchanged.
10. REQ-LIVE-10: IF an `advanceTo(now)` call arrives while the switch is pressed, THEN THE Live_Decoder SHALL leave the Partial_Sequence, the completed Decoded_Items and the pressed state unchanged, and SHALL record now as the latest received timestamp.
11. REQ-LIVE-11: FOR ALL Valid_Event_Sequences, Calibrations and Timing_Configs, feeding the events to a new Live_Decoder in order, with `advanceTo` calls inserted at any non-decreasing times between them, followed by `advanceTo(t)` where t is the last release timestamp plus the larger of the Debounce_Time and the Letter_Gap_Threshold, SHALL leave the Live_Decoder holding Decoded_Items equal to the Batch_Decoder output for the same input and an empty Partial_Sequence (live and batch equivalence property).
12. REQ-LIVE-12: WHEN the Live_Decoder, configured with the Calibration in REQ-BATCH-5 and the default Timing_Config, receives a press at 0, a release at 100,000 and `advanceTo(130,000)`, THE Live_Decoder SHALL hold a Partial_Sequence of `.`, no completed Decoded_Items and a not-pressed state.
13. REQ-LIVE-13: WHEN the Live_Decoder in the state reached at the end of REQ-LIVE-12 receives `advanceTo(800,000)`, THE Live_Decoder SHALL hold exactly one completed Decoded_Item, a Letter_Item `E`, and an empty Partial_Sequence.
14. REQ-LIVE-14: IF the time since a release reaches the Debounce_Time as in REQ-LIVE-4 and the released Press lasted less than the Debounce_Time, THEN THE Live_Decoder SHALL discard that Press, append no Symbol, and leave the Partial_Sequence and completed Decoded_Items unchanged. Later Gaps SHALL be measured from the release of the last Press it appended, as in REQ-DEBOUNCE-5.

### Requirement 9: Engine purity, structure and privacy

**User Story:** As a Sounder developer, I want the timing engine to follow the same rules as the rest of morse_core, so that it runs anywhere Dart runs and never leaks what the user keyed.

#### Acceptance Criteria

1. REQ-ENGINE-1: THE Timing_Engine SHALL meet morse-core REQ-PURE-1: the Morse_Core `pubspec.yaml` SHALL still list zero packages under `dependencies`, and every Timing_Engine file under `lib/` SHALL import only `dart:core`, `dart:collection`, `dart:convert`, `dart:math`, `dart:typed_data`, `dart:async` or other files of Morse_Core.
2. REQ-ENGINE-2: THE Timing_Engine SHALL compute every result, and every Timing_Input_Error, only from its arguments and the state of the instance it is called on. It SHALL NOT read the clock, a random number source, files, network or environment variables. It SHALL NOT read or write any top-level variable or static field that is not `final` or `const`. A test for this criterion SHALL show that two new instances given the same sequence of calls return equal results, or raise Timing_Input_Errors with the same error kind and event index.
3. REQ-ENGINE-3: THE Timing_Engine SHALL place each public class and each public enum in its own file under `lib/src/`, named as the type in `snake_case.dart`, with exactly one public type per file. Morse_Core SHALL export every one of these types from `lib/morse_core.dart`, so that a consumer can use the whole Timing_Engine API with that single import and without importing any file under `lib/src/`.
4. REQ-ENGINE-4: THE Morse_Core public API SHALL consist of `CodeTable`, `MorseEncoder`, `MorseDecoder`, `MorseFormatException` and the public types of the Timing_Engine. This criterion replaces only the public-API sentence of morse-core REQ-PURE-6. The other clauses of REQ-PURE-6 (no identifier `Awesome`, no `morse_core_base.dart` or `morse_core_test.dart`, and a `pubspec.yaml` description and `example/` files limited to the public API) still apply.
5. REQ-ENGINE-5: THE Timing_Engine source under `lib/` SHALL contain no `print` call, no `dart:developer` import or `log` call, and no write to standard output, standard error or any other sink. The `toString` and message of every Timing_Input_Error and Calibration_Rejection SHALL NOT contain any Symbol sequence taken from the input, any character decoded from the input, or the decimal form of any input timestamp or measured duration. The event index allowed by REQ-EVENT-4 and the counts allowed by REQ-CAL-13 are the only exceptions. A test for this criterion SHALL use timestamps of at least 1,000,000 that differ from every event index.
6. REQ-ENGINE-6: THE Timing_Engine SHALL put a `///` doc comment on every public class, enum, enum value, constructor, method, getter, setter and field. Each doc comment SHALL cite at least one requirement ID in the form `REQ-<AREA>-<n>` that exists in this document or in the morse-core requirements document. For Timing_Engine files, this criterion replaces the rule in morse-core REQ-PURE-7 that cited IDs must come from the morse-core document.
7. REQ-ENGINE-7: WHEN `dart analyze` runs in `packages/morse_core`, THE Morse_Core SHALL report zero errors and zero warnings across `lib/` and `test/`.
8. REQ-ENGINE-8: WHEN `dart test` runs in `packages/morse_core`, THE Morse_Core test suite SHALL include at least one passing test whose name begins with each of REQ-ENGINE-1 through REQ-ENGINE-6, checking that criterion against the package source or the public API.

REQ-PBT-1: THE Morse_Core SHALL include, in `packages/morse_core/test/`, at least one property-based test using `kiri_check` (already pinned as a dev dependency in `pubspec.yaml`) for each of REQ-DEBOUNCE-7, REQ-DEBOUNCE-8, REQ-DEBOUNCE-9, REQ-CAL-15, REQ-TIMING-2, REQ-TIMING-7, REQ-TIMING-8, REQ-TIMING-10, REQ-BATCH-8, REQ-BATCH-9 and REQ-LIVE-11. Each of these tests SHALL check at least 100 generated cases per `dart test` run.
